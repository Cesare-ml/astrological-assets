# Astrological Assets — instructions for human and AI contributors

**Current state: public repository; original asset rights review remains incomplete.** The original code/tooling uses CPAL-1.0. Images have only private-sharing permission; public release is blocked pending independent rights review.

## Non-negotiable rules

1. Work in English in all source code, documentation, issues, PR titles and descriptions.
2. Read `README.md`, `docs/ROADMAP.md`, `docs/RIGHTS_AND_REVIEW.md`, `docs/PUBLIC_RELEASE_CHECKLIST.md`, `docs/ASSET_SCOPE.md` and `docs/MIGRATION_PLAN.md` before changes.
3. Preserve the **original developer attribution** in `LICENSE` Exhibits A/B and `NOTICE`: `Powered by VirgoStars` and `https://www.virgostars.it/`. Respect CPAL Sections 14 and 15 when applicable.
4. **Do not assume that CPAL licenses images.** The owner has selected CC BY 4.0 for their original artwork in `catalog/artwork-license-decision.json`, but any third-party source rights remain subject to human review. Private permissions in `catalog/approvals.json` are not public permissions. Never manufacture, infer, or sign `catalog/publication-approvals.json` entries on behalf of the rights holder. A human rights holder must supply explicit public redistribution evidence and a suitable asset license.
5. The repository is already public. Audit **all historical content and Git references** for unlicensed or confidential material, remembering that removing files now does not revoke copies or public Git history already fetched. Avoid reintroducing unreviewed material. If material must be withdrawn, escalate promptly to the owner and follow repository-host guidance; a new clean history alone will not undo past exposure.
6. Never automatically copy the entire `virgo-stars` asset tree. Candidate metadata is not permission; verify source Git blob SHA, size, exact path and approval.
7. Keep the importer dry-run by default. Require explicit approval for `--apply`. Preserve existing paths, casing, hashes and file formats. Do not silently rewrite missing `risuonatore-solare-bianco.png` references.
8. Never add user natal charts, account data, credentials, AWS configuration, secret keys, web-only media, unlicensed graphics, or font binaries without full license review.
9. Production remains in `virgo-stars/public/assets` until a separately reviewed, tested migration. `astrological-charts` owns renderer code; this repository owns vetted assets and their verification tooling. Avoid duplicate Angular output URLs.
10. Run `npm test`, `npm run audit:catalog`, `npm run verify:pack`, and `npm run check:public-release` as applicable. The last command is intentionally blocked until public rights are granted; do not bypass or weaken it.
11. Use focused branches and PRs, report limitations, and do not perform merges, change repository visibility, publish releases, deploy, or add GitHub Actions without explicit owner authorization.
12. Never mistake metadata/hash checks for legal proof of rights. If a license, authorship, font origin or third-party restriction is uncertain, block the asset from public distribution and request human review.

## Planned original VirgoStars Astro font

The 22-glyph original-font initiative is **planned**, not implemented. A planning-only Unicode registry exists at `specs/virgostars-astro.v0.json`; validate it with `npm run check:astro-spec` and `npm test` before changing symbol coverage. For future **independently authored, private** TTF/WOFF2 builds, use the read-only validation tool documented in `docs/PRIVATE_FONT_VALIDATION.md`. For offline optical QA, use `scripts/create-private-font-specimen.py` per `docs/PRIVATE_FONT_VISUAL_QA.md`; its generated HTML **embeds the entire proprietary font**, so both the font and HTML must remain outside this public checkout and never be attached to public issues or PRs. It must not copy or add font binaries to this public repository. **The privately delivered v0.1 geometric prototype was rejected by the owner for poor visual quality. A subsequent set of 22 independently generated glyph images has been approved, and a separate private v0.2 prototype has been compiled from those approved new images.** Follow `docs/APPROVED_GLYPH_IMAGES_V02.md`: preserve the approved images as the new source of truth, do not revert to the v0.1 buffered geometry, and do not treat image approval as authorization to publicly redistribute the proprietary TTF/WOFF2.  Do not use its outlines as a production baseline or repeat its monoline/buffered-stroke construction as if it were a redesign. See `docs/PROTO_V01_VISUAL_REJECTION.md`: present independently authored Virgo/Scorpio/Capricorn candidates first, require explicit owner visual approval, and only then build the remaining family. `docs/PRIVATE_PROTOTYPE_QA.md` remains a record of technical tests, not approval. Track it in [issue #8](https://github.com/Cesare-ml/astrological-assets/issues/8) and [roadmap](docs/ROADMAP.md). The owner explicitly selected the *traditional astrological glyph variants* visible in their Astro-SemiBold reference; preserve those conventional symbol identities, **not** the actual font contours.

Do not copy, trace, convert, vectorize, extract, modify, train on, or redistribute the reference `ASTRO-SE.TTF` file or glyph outlines. Work from independently created vector sources, use the specified Unicode mappings, and keep unapproved proprietary font source/binaries outside this public repository. Get an explicit font license and bundle/embedding rights before introducing new binaries into any public client. This project does not grant retroactive permission for historical raster images.

## Contributions

Prefer small, auditable improvements to validation, packaging, accessibility, documentation and compatibility with Angular/Three.js and the offline Astrolabio. Update tests and documentation with any behavior change. Do not duplicate astronomical calculations here.
